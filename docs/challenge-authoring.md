# 日本語テーマ・課題文の作成規則

この文書は、UltiType の課題文を追加・修正する AI エージェントと開発者が遵守する仕様です。新規作成、再生成、既存テーマの更新にも適用します。

## 言語・件数・文字数

- 今回のテーマ拡張は日本語のみ。既存の英語モードは維持し、日本語のテーマを英語へ自動翻訳しない。
- **各テーマを作成するたびに、短文40種類と長文10種類を用意する。** 同じ文の使い回しや単なる語句の差し替えで件数を水増ししない。
- 短文は、漢字交じりの表示文で **15～30文字（両端を含む）**。1行につき1課題とする。
- 長文は、漢字交じりの表示文で **300～600文字（両端を含む）** をひとかたまりとする。段落全体に筋の通った話題を持たせる。
- 長文内の改行は許可する。空行は別の課題との区切りになる。既存パーサーは長文内の改行を除いて連結するため、文字数もその表示結果で判定する。
- 文字数は `Array.from(challenge.display).length` で数える。ふりがな注釈やローマ字入力列の長さではない。句読点は表示文字として数える。

## 文体

- **生活に寄り添う、素朴で普通の文章を主流にする。** 食事、買い物、趣味、学習、家族との会話、通勤など、身近な題材を読みやすい言葉で扱う。
- 例えば「関係代名詞とは、～～～で、～～～である。」という定義の説明より、「日本人の先生の話す英語もなかなか聞き取れない。」のような日常の文章を優先する。
- **特に長文では、豆知識的な内容を含めることを積極的に推奨する。** テーマに関係する歴史、由来、仕組み、種類ごとの違いなど、読んで知る楽しさのある内容を取り入れる。
- 日常の出来事に豆知識を自然に織り込む文章も、身近な題材の背景を平易に説明する文章も採用できる。通常のテーマでも、歴史や仕組みの説明そのものを長文の中心にしてよい。
- 長文の好ましい構成例：「通勤電車と言ってもいろいろな種類があるが、その始まりはXX年のXX鉄道のXX路線ができたのがはじめという説が有力である。この路線は～」。これは構成を示す仮の例であり、年号・鉄道名・路線名・説の位置付けは資料を確認してから記入する。
- 学術的な文章も、それ自体を一つのテーマとして扱うことはできる。各テーマで、読みやすさと内容のつながりを大切にし、定義の羅列に偏らないようにする。
- 同じ書き出し・展開・結びや、文字数だけを満たす共通の追記を大量に繰り返さない。各長文に異なる具体的な出来事、豆知識、視点を用意する。
- 歴史、由来、分類などの事実や、年号・固有名詞は、信頼できる一次資料で確認する。「はじめ」「有力な説」といった位置付けにも根拠を持たせ、諸説のある話を一つの確定事実として書かない。

### 会話・記号・語尾

- 長文にカギカッコを使用してよい。特に「ああ、間に合わない！」「豚骨ラーメンって、なんで白いんだろう？」「早く出ないと遅刻するよ！」のような、自然な口語の会話や心の声を積極的に取り入れる。
- カギカッコ、括弧、感嘆符「！」、疑問符「？」は、内容に合わせて事前の予告や確認なしに使用してよい。記号は文章の意味や読みやすさに合わせて使う。
- 一般的な文章で使う記号に波ダッシュ「～」も含める。時間や数量の範囲（例：`5～10分`）など、自然な文脈で使用してよい。
- 常体（だ・である調）と敬体（です・ます調）の長文を、どちらも用意する。各テーマで両方の文体を読める構成にする。
- **一つの長文の地の文は、一方の文体に統一する。** 正当な理由なく常体と敬体の語尾を混在させない。
- カギカッコ内の話者の口調や資料の引用など、理由のある文体の違いは認める。例えば敬体の地の文に「ああ、間に合わない！」というせりふを入れてもよい。話者のせりふと地の文の区切りを明確にする。

### 数字

- 漢数字を原則とせず、半角のアラビア数字 `0～9` も自然に混ぜる。年・日付・時刻・所要時間・数量など、文脈に合う表記を選ぶ。
- **表示文がアラビア数字なら、入力も同じ数字を必要とする。** 例えば表示の `1` を `いち` / `ichi` で代替しない。
- アラビア数字は原則として本文にそのまま記述し、読み仮名へ置き換える注釈（例：`[1](いち)`）を付けない。`2026[年](ねん)` のように、数字の後の漢字に読みを付けることはできる。

## 読み・ローマ字入力

- 既存の `src/lib/challenges.ts` のパーサーとローマ字変換を使い、テーマ専用の入力方式は追加しない。
- このアプリの入力では「ぢ」は `di`、「づ」は `du` とし、「じ」（`ji` / `zi`）・「ず」（`zu`）と区別する。「ちぢれためん」は `chidiretamen` などで入力し、`chijiretamen` や `chiziretamen` は許容しない。
- 漢字の読みは `[表示](よみ)` の注釈で記述する。未注釈の漢字を残さない。複数文字の語全体への注釈も使用できる。
- 読みは文脈に合わせる。送り仮名を注釈の読みへ二重に入れない。特に `[会](あ)って` を `[会](あっ)って` としない。
- 記法文字を表示する場合は `\[`, `\]`, `\(`, `\)`, `\\` のようにエスケープする。
- 日本語本文の括弧には `（ ）` も使える。ローマ字入力では `「 」` を `[ ]`、`（ ）` を `( )`、`！ ？` を `! ?` に対応させ、表示文の日本語記号は維持する。
- 波ダッシュ「～」はローマ字入力で `~` に対応する。アラビア数字は `0～9` の数字キーで入力する。
- 読み・ふりがな・ローマ字・IME入力の表示対象は、すべて同じ選択テーマのデータから取得する。

## テーマと週次切り替え

今回の追加対象は、ユーザーが列挙した次の **8テーマ**（依頼文の「5テーマ」より、具体的な一覧を優先）とする。

1. 英語学習 (`english-learning`)
2. 魚の種類 (`fish-types`)
3. 回転すし (`conveyor-sushi`)
4. 高級寿司 (`luxury-sushi`)
5. ラーメンの歴史 (`ramen-history`)
6. ラーメンの種類 (`ramen-types`)
7. 音楽のジャンル (`music-genres`)
8. 通勤電車 (`commuter-trains`)

既存の「タイピングのコツ」(`typing-tips`) も残し、同じ40短文・10長文の規則にそろえる。

- 本番では、**毎週月曜日の午前6時、日本時間（Asia/Tokyo、UTC+09:00）** に自動でテーマを切り替える。利用者の端末のタイムゾーンに左右されない。
- ローテーションの基準は **2026年10月26日（月）06:00 JST＝英語学習**。上の8テーマ、タイピングのコツの順で循環する。直前の週はタイピングのコツとなる。
- 静的サイトでも日時から同じテーマを計算できるようにする。サーバー上の cron や毎週の再ビルド、AIによる毎週の自動生成は必要としない。
- 入力中の課題文を時刻境界で差し替えない。新しいテーマは次のセッションの準備・リセット時に適用する。
- 開発サーバーでは、テーマ選択のプルダウンで全テーマを任意に確認できる。「自動」に戻すと週次切り替えへ戻る。
- 開発用の手動選択は本番では適用しない。今回は新たな開発サーバーをエージェントが起動しない。

## 保存場所・確認

- 新テーマの短文は `src/lib/challenge-data/themes/<id>-practice.txt`、長文は `src/lib/challenge-data/themes/<id>-production.txt`。
- 既存のタイピングのコツは `ja-practice.txt` と `ja-production.txt`。
- frontmatter の `type` は短文が `ultitype_sentence_short`、長文が `ultitype_sentence_long`。
- 追加後は対象テストで、各テーマの40/10件、表示文字数、重複、漢字の読み、既存方式によるローマ字変換を確認する。
- 本文を自動検査に通すためだけに、制限やテストを緩めない。課題文を修正する。

## 今回の歴史記述に用いた資料

各テーマの長文に追加した豆知識と、課題ごとの出典対応は [長文の豆知識と参照資料](./challenge-trivia-sources.md) に記録する。

「ラーメンの歴史」では、普段の食事や資料を読む場面に事実を織り込む文章に加え、由来や普及の経緯を平易に説明する長文も積極的に採用する。確認した事実を、読み物としてつながりのある文章にまとめる。

- [新横浜ラーメン博物館：淺草 來々軒の復活に関する発表](https://www.raumen.co.jp/old_site/information/news_001083.html) — 浅草の来々軒の1910年開業を確認。「日本最初のラーメンそのもの」とは断定しない。
- [日清チキンラーメン：よくある質問](https://www.chickenramen.jp/faq/) — 安藤百福の発明、1958年の発売を確認。

創作した家族の会話・食事・訪問の場面は、特定の実在人物や店舗の体験談を転載したものではない。
