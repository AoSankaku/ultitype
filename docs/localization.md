# UI翻訳と初期表示

UIは第一言語範囲の `ja` / `en` と、第二言語範囲の20言語・地域に対応しています。練習言語は `ja` / `en` のみで、課題本文は翻訳しません。英語の課題テーマは既存の「タイピングのコツ」1種類です。

## 翻訳データ

`locales/<code>.yaml` を編集します。`meta` に言語コード・母語での表示名・文字方向、`messages` に表示文を記述します。既存の日本語原文をキーとする項目に加え、共有テンプレートなどに意味を表すキーを使っています。

- 翻訳文をTS/TSX内の言語分岐へ追加しないでください。
- 各カタログのキーをそろえ、`{mode}` や `{count}` などのプレースホルダーを維持してください。
- キーの重複、空の値、プレースホルダーの欠落は検証エラーになります。
- 国名は `Intl.DisplayNames` でUI言語に合わせます。課題データの表示名・本文は書き換えません。
- 表示言語を増やす場合は `locale-codes.ts` の対応コードと `locale-catalogs.ts` の静的インポートも追加します。

YAMLは共通ローダーでビルド時にJavaScriptへ変換します。ブラウザーにYAMLパーサーを追加せず、翻訳データの取得リクエストも発生しません。開発用Webpackと本番用Turbopackの両方で同じローダーを使います。

## 初期表示

静的エクスポートのHTMLは日本語を既定値にします。`head` 内の短い同期スクリプトが保存済みの言語・配色を描画前に読み取り、`lang` / `dir` / 配色を設定します。保存言語が既定値と異なる場合は、アプリ部分をレイアウトを維持したまま一時的に隠します。保存設定の読み込みと翻訳済みDOMの反映が完了した後、レイアウトエフェクトで表示します。

これによりハイドレーション時のHTMLを直接翻訳することなく、誤った言語・配色のちらつきを防ぎます。ストレージが使えない場合や値が不正な場合は、日本語の既定表示を継続します。JavaScriptが無効な場合も既定のHTMLが表示されます。アラビア語のUIは右から左ですが、練習本文と入力欄は練習言語に従い左から右のままです。

## 検証

```sh
bun scripts/verify-ui-locales.ts
bun test app/_lib/locale-codes.test.ts app/_lib/locale-bootstrap.test.ts app/_lib/locale-catalogs.test.ts
bun run typecheck
bun run build
```

FOUCの実ブラウザー検証は `scripts/verify-locale-first-paint.mjs` で行えます。Playwrightを利用できる環境で、必要なら `ULTITYPE_PLAYWRIGHT_MODULE` にそのモジュールパスを指定して実行します。本番ビルドの `out/` をブラウザーのリクエストに直接返すため、開発・プレビューサーバーを起動しません。遅延したJavaScript、保存言語、再読み込み、RTL、ストレージの破損・拒否を確認し、ブラウザーは終了時に閉じます。
