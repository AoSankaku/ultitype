# 長文の行間・プレビュー・進捗表示の修正

2026-10-25。ユーザー報告の画面で、前行のマーカーと次行のルビの重なり、漢字文と入力中の読みの進捗のずれを確認した。

## 原因と変更

- 長文は短文と共通の `kanjiLineHeight`（初期値1.45倍）を使っていた。長文専用の永続設定 `productionLongTextLineHeight` を追加し、初期値・旧データに項目がない場合の値を2.1倍にした。値の範囲は既存の行間と同じ0.8～2.5倍。
- 「入力画面設定」の「長文モードの行間」で変更できる。本文、表示領域の高さ、フェード、スクロール量、次の課題との余白は同じ行間を使う。短文用の行間は独立している。
- 設定画面の「プレビューの課題文」で短文／長文を切り替えられる。長文は実際の長文データと本番IMEなしの表示を使い、切り替え時に再生位置をリセットする。
- 入力用の読みは平仮名に正規化される一方、漢字文のマーカー計算は片仮名の表示文字を直接数えていた。「ラーメン」は本来6トークンのところ4、「スープ」は5のところ3と数えられ、その後の位置が先へずれていた。
- 共通の読みトークン処理で、変換表の参照には正規化した文字を使い、表示文字は元の片仮名を維持するように修正した。「ッ」も「っ」と同じ促音マーカー単位として扱う。

## テストの意図と結果

先に回帰テストを追加し、以下の4つが失敗することを確認した。

1. 片仮名と対応する平仮名でローマ字・読みトークン範囲が一致すること。
2. 報告と同じ「昼休みに同僚と豚骨ラーメンを食べに行った。白く濁ったスープを見て。」で、入力が `…shirokunigottasu-` の時点では「プ」が現在位置、「見」が未入力であること。`puwo` を入力すると「見」とルビの「み」が現在位置になること。
3. 同じ入力に対する入力済み漢字表示が、「スープを」まで先に変換されないこと。
4. 片仮名の「カップ」のマーカーが「カ」「ップ」の単位になること。

## 実ブラウザーでの検証

ユーザーが起動している `http://localhost:3000/settings/screen` を、隔離したヘッドレスChromeで検証した。

- 初期表示は短文で、プルダウンから長文に切り替えると実際の長文表示になる。
- 初期値2.1倍で、32pxの漢字の行送りは67.2px、5行の表示領域は336px。複数の行について、ルビと前行の本文・下線のための余白をDOM座標で確認した。
- UIで2.4倍に変えると、行送り76.8px・表示領域384pxへ即座に変わる。保存値と再読み込み後のUIも2.4倍を維持する。
- 短文へ戻すと長文表示はなくなり、短文の行間は1.45倍のまま。
- ページの実行時エラーは0件。プレビュー画像も目視確認した。
